Introduction & Learning Philosophy
Learning by Building & Reflecting
A brief view of how I learn, what I value, and how that shows up in my projects and work.

I treat learning as a loop: understand → build → break → fix → document. Concepts become real only when they survive real constraints like time limits, broken APIs, and unclear requirements.

My interests sit where theory meets application: algorithms in real systems, databases backing actual products, and Web3 used for real-world use cases like lending or property.

Core values:

  • Clarity: keeping architectures and code readable, not just clever.
  • Ownership: taking responsibility from idea to working prototype.
  • Impact: choosing projects that solve something concrete.
Project-based Learning Systems Thinking Human-Centered Tech
How I approach a new concept

From Theory to Working Prototype

  • Skim the big picture and core idea.
  • Relate it to a real use case (e.g., lending, real estate, productivity).
  • Build a small demo or tool using that concept.
  • Note down what failed, what was confusing, and how I fixed it.

Global Awareness & Ethical Considerations
Thinking Beyond Just Code
Some of the questions I ask about impact when building systems.

Working on a micro-lending idea made it clear that financial systems can help or harm, depending on how they are designed. The same line of code can be helpful in one context and unfair in another.

Transparency vs. Privacy

On-chain Data

Recording loan activities on a public chain gives transparency, but personal details should not be fully exposed.

Fairness

Access to Credit

Any scoring logic needs to be checked so it doesn’t unfairly block certain groups or locations.

Responsibility

Role as a Developer

I try to ask: “Who could be harmed if this system is misused?” and “Is there a safer way to design it?”
